THE ENGINEERING PROBLEM

How do you make a hydrofoil move precisely enough to become an experiment?

Marine-energy experiments require repeatable mechanical motion. The hydrofoil actuator needed to move to defined angular positions, return to a reference position, oscillate between positions, and hold position using an electromagnetic brake.

The project began as a hardware-control problem: generate the correct motor pulses and coordinate the actuator with the mechanical system.

It evolved into a systems-engineering problem involving embedded firmware, communication, abstraction layers, supervisory software, and future multi-controller scaling.

// Representative excerpt

const int STEP_PIN  = 4;
const int DIR_PIN   = 3;
const int BRAKE_PIN = 7;

const long PULSES_PER_REV = 12500;

void stepMotor(long pulses) {

    for (long i = 0; i < pulses; i++) {

        digitalWrite(STEP_PIN, HIGH);
        delayMicroseconds(500);

        digitalWrite(STEP_PIN, LOW);
        delayMicroseconds(500);
    }
}

void releaseBrake() {
    digitalWrite(BRAKE_PIN, HIGH);
}

DEBUGGING CASE STUDY

The motor taught me that code can be correct and still be wrong.

The initial commanded and observed angular motion did not agree. Investigation showed a mismatch between the microstepping configuration assumed by the firmware and the physical driver configuration.

SYSTEM ARCHITECTURE

The actuator worked. The architecture needed to scale.

Direct Arduino control is effective for one actuator. A research facility is different: multiple experimental systems may use different controllers, drivers, sensors, and communication interfaces.

I contributed to the transition toward a modular architecture in collaboration with the UMass research team.

The shaft moved first.

I began this project knowing little about stepper motors, embedded control, or supervisory systems. Building the actuator forced me to connect mechanical hardware, electronics, firmware, communication, and software into one working system.
