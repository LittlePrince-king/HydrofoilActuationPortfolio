02
ACTUATION SYSTEM

Controlled motion as an experimental subsystem

Marine-energy experiments require repeatable positioning, controlled motion, and reliable integration between mechanical, electrical, and software components.

01 Mechanical System Hydrofoil shaft
02 Actuator NEMA 17 motor
03 Driver CL57T
04 Controller Arduino
05 Supervision Python / SCADA

Required behavior

  • Move to defined angular positions
  • Return to a known reference position
  • Oscillate between commanded positions
  • Maintain position using an electromagnetic brake
  • Provide a foundation for higher-level control

Subsystem boundary

The work focused on the electromechanical actuation subsystem and its software interfaces. Full hydrodynamic characterization and final flow experiments were outside the testing scope.

// Representative excerpt
// Initial low-level actuator implementation

const int STEP_PIN  = 4;
const int DIR_PIN   = 3;
const int BRAKE_PIN = 7;

const long PULSES_PER_REV = 12500;

void stepMotor(long steps, bool direction) {

    digitalWrite(DIR_PIN, direction);

    for (long i = 0; i < steps; i++) {

        digitalWrite(STEP_PIN, HIGH);
        delayMicroseconds(400);

        digitalWrite(STEP_PIN, LOW);
        delayMicroseconds(400);
    }
}

void releaseBrake() {
    digitalWrite(BRAKE_PIN, HIGH);
}

VALIDATION

Hardware/software configuration validation

Initial angular discrepancies demonstrated the importance of reconciling software assumptions with the physical driver configuration.

01 Observed discrepancy Commanded and observed angular motion differed.
→
02 Configuration review Firmware pulse assumptions were compared with driver settings.
→
03 Parameter reconciliation Pulse-per-revolution assumptions were corrected.
→
04 Retest Positioning behavior was evaluated again.

Control accuracy depends on the assumptions connecting the physical system and its software representation.

POSITIONING TEST

Angular repeatability

The actuator was moved approximately 90°, then commanded through approximately 3° increments over 30 cycles before returning to the original position.

  • Static positioning demonstrated
  • Oscillation behavior demonstrated
  • No obvious missed-step behavior observed
  • Brake control demonstrated
  • Target repeatability: approximately ±1°
SCOPE BOUNDARY

This work validated the actuation subsystem. Full hydrodynamic characterization and final flume/flow experiments were outside Yatharth's testing scope.

09
ENGINEERING CONCLUSIONS

Key engineering principles

01

Physical assumptions matter

Software parameters must correspond to the actual hardware configuration.

02

Interfaces require validation

Errors often occur at the boundaries between mechanical, electrical, and software layers.

03

Systems exceed components

Reliable behavior depends on interactions among the actuator, driver, controller, communication, and supervisory layers.

04

Architecture determines scalability

A single-actuator implementation can become a constraint when applied to a larger experimental system.
