EMBEDDED CONTROL

Low-level actuator control.

The initial implementation used Arduino firmware to directly generate motor pulses, calculate target positions, and operate the electromagnetic brake.

ARDUINO / INITIAL CONTROL IMPLEMENTATION 
// Representative excerpt
// Initial low-level actuator implementation

const int STEP_PIN  = 4;
const int DIR_PIN   = 3;
const int BRAKE_PIN = 7;

const long PULSES_PER_REV = 12500;

void stepMotor(long steps, bool direction) {

    digitalWrite(DIR_PIN, direction);

    for (long i = 0; i < steps; i++) {

        digitalWrite(STEP_PIN, HIGH);
        delayMicroseconds(400);

        digitalWrite(STEP_PIN, LOW);
        delayMicroseconds(400);
    }
}

void releaseBrake() {
    digitalWrite(BRAKE_PIN, HIGH);
}

09
ENGINEERING CONCLUSIONS

Four principles from the system.

01

Physical assumptions matter

Software parameters must correspond to the actual hardware configuration.

02

Interfaces require validation

Errors often occur at the boundaries between mechanical, electrical, and software layers.

03

Systems exceed components

Reliable behavior depends on interactions among the actuator, driver, controller, communication, and supervisory layers.

04

Architecture determines scalability

A single-actuator implementation can become a constraint when applied to a larger experimental system.

PROJECT SUMMARY

A validated actuation subsystem. A path toward modular control.

The project combined electromechanical integration, embedded control, positioning validation, and software architecture within a marine-energy research environment.
